# 2026-09-09 项目审查

## 判断标准

这个项目的核心价值是帮助研究者获得可追溯的文献依据。成熟度首先取决于选中资料是否隔离、结论能否核对、失败是否可见、操作是否可恢复，以及运行是否可复现。模型名称、框架数量和界面装饰不能替代这些条件。

采用“攻击假设 → 可复现反例 → 修复 → 回归验证”的审查方法。初始版本 29 项测试全部通过，但测试主要覆盖顺利流程，无法证明下面这些边界可靠。此次审查和测试由同一主 Agent 完成，未将其宣称为多个独立审查者的一致结论。

## 发现与处理

| 优先级 | 原问题及反例 | 处理 |
| --- | --- | --- |
| P1 | 固定 Chroma 集合持续追加：取消选择论文或缩短文档后，旧片段仍可能出现 | 按内容及 embedding 模型命名不可变集合；查询结果再校验当前片段集合；批量建索引 |
| P1 | 使用 `1/(1+distance)`，无关向量仍得到足以超过 0.12 阈值的分数 | 明确余弦距离并转换为相似度；默认本地模式采用关键词检索，避免随机哈希碰撞被当作语义证据 |
| P1 | 任意 `[99]`、无引用或空输出直接呈现为正式答案 | 检查引用范围与非空输出，最多一次修正，仍失败则扣留回答；显式标注这不是语义事实校验 |
| P1 | 不可信资料和问题拼到单一提示文本，没有清楚的角色边界 | 系统约束与 JSON 证据分离；资料中的指令不具备工具权限 |
| P1 | 新 Markdown 界面可能把模型伪造图片变成外部请求 | 使用 Markdown AST 禁用图片、原始 HTML 和未授权链接，保留可信来源链接 |
| P1 | 删除函数先清理文件名再判断范围：`../paper.md` 可映射到仍存在的库内文件 | 删除必须使用完整、精确的管理文件名；拒绝路径变形及符号链接 |
| P2 | 上传依赖扩展名，未限制空文件、大小、编码；并发同名写入可能覆盖 | 批次预校验、20/60 MB 限制、UTF-8/签名检查、临时文件完整写入后排他发布 |
| P2 | 一份损坏或复杂 PDF 中断整个资料加载 | 逐文件错误隔离；PDF 25 秒子进程时限；页数、文本量和知识库片段上限 |
| P2 | arXiv 查询缺少布尔分组，错误与空结果混为一谈，网络等待不可控 | 按官方语法显式分组；常用中文术语映射；15 秒网络超时、响应大小限制、缓存和请求间隔；独立工具错误状态 |
| P2 | 向量查询阶段失败未降级，界面仅显示“配置的模型” | 查询失败也可回退关键词，结果记录实际 backend 和降级原因 |
| P2 | 回答只保存在函数局部变量中，控件交互后消失；空库禁止外部检索 | 会话内保留完整问答、来源及提问时范围；空库仍可查询 arXiv；切换范围提示旧答案依据 |
| P2 | 状态把离线回答、模型失败等混在“已回答/正常”中 | 明确 demo、answered、insufficient_evidence、model_error、invalid_input 状态及真实模型调用数 |
| P2 | 日志每次读全部内容；合法 JSON 数组或 null 会触发异常 | 有界尾部读取、对象结构检查、容忍损坏记录、limit=0 行为修复 |
| P2 | 依赖只有下限、无统一安装入口，全局环境有冲突 | pyproject 统一包声明和依赖范围、独立 .venv、安装与依赖一致性复验 |
| P3 | 大型说明型页头挤占提问空间，移动端标题遮挡，引用来源没有可对照编号 | 重构三个工作区，编号来源、导出、删除确认，响应式布局与实际截图检查 |

## 架构决定

保留 Streamlit、LangGraph 与现有文档模型，新增 `service.py` 作为 UI 与业务之间的调用边界。资料加载、检索、生成、外部访问、输出渲染、运行记录分别由独立模块负责。这样可以用 Streamlit AppTest 验证界面，用普通单元测试验证业务，再用本地 HTTP 服务验证模型供应商协议。

Agent 的外部能力保持为只读 arXiv 检索。流程使用有限工具调用与有限修正，不执行来源文档中的指令。每份证据最多截取 3500 字、最多六份来源，输出和模型网络重试均有限制。

默认本地检索不依赖下载模型或付费。真正的语义模型是显式配置项。对于低相关边缘命中，使用绝对阈值与最佳命中的相对阈值共同筛选；这些阈值是工程启发式，不是经过领域标注数据校准的置信度。

## 验证范围与限制

- 回归包含真实 Chroma 的文档变更隔离、本地 HTTP 的真实 ChatOpenAI 客户端、Streamlit AppTest、并发上传、损坏 PDF 和解析超时。
- 提示注入测试验证角色边界、工具边界与输出展示边界，不能证明真实模型永远不会被恶意文档诱导。
- 引用格式检查可以抓住伪造编号和缺失引用，不能发现“真实来源编号 + 不被原文支持的断言”。需要真实领域数据集和人工逐句核验才能评价这一点。
- 确定性评测使用固定模型响应，仅测流程，不作为回答质量分数。
- API 协议测试使用本机模拟服务，没有消耗真实模型额度。真实供应商的余额、可用性及复杂问题质量不包含在该测试的证明范围内。
- 本地语义模型权重未为此次审查额外下载；其包装器和失败降级已有测试，真实跨语言召回质量尚需领域评测。
- 历史索引快照、历史导出和可选日志有各自的数据生命周期，删除资料原文件不是安全擦除所有副本。
- 该版本是单用户本地研究工具。公网多用户发布需要身份认证、资料权限和资源隔离，这与本轮本机工作台的验收范围不同。

arXiv 查询语法依据：[arXiv 官方 API 手册](https://github.com/arXiv/arxiv-docs/blob/develop/source/help/api/user-manual.md)。
